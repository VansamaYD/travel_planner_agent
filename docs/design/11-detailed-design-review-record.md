# DD-11 详细设计最终评审记录

> 版本：1.0-review
> 评审日期：2026-08-30
> 对比基线：SRS 1.0-baseline、运行流程与设计准入复核
> 当前结论：详细设计通过，可进入实现契约与骨架开发

## 1. 评审范围

本次评审覆盖 DD-01～DD-13（DD-11 为总评审记录），并反向对比：

- 267 条 FR/NFR；
- DR-001～007；
- AC-001～011；
- 已冻结的架构、Agent、Provider、地图、OCR、小红书、成本、性能和自托管口径；
- 文档间本地链接、代码围栏、需求域和关键常量。

## 2. 评审方法

1. 从 SRS 的需求定义行提取唯一 ID，不依赖人工总数；
2. 按需求域映射到设计文档与测试层；
3. 对关键行为进行正向流程和逆向失败检查；
4. 使用 `scripts/validate_design_docs.sh` 检查机械一致性；
5. 对发现的问题修订后重新执行，直到无失败；
6. PoC 项不伪装成已验证实现，保留 Go/No-Go 和降级路径。

## 3. 迭代记录

### Iteration 1：结构与架构

- 建立 11 份编号文档和依赖关系；
- 固化模块化单体、SQLite WAL、单 Worker、REST+SSE、Proposal 两阶段提交、自有 Runtime、高德主地图和重任务子进程；
- 结果：未发现与准入复核冲突。

### Iteration 2：数据、事务、API 和 Agent

- 将当前 Trip、不可变 Version、Proposal、OrderEvent、Expense 冲销、Evidence 和 Audit 分离；
- 固化乐观锁、幂等、Outbox 和禁止网络调用进入写事务；
- 固化 API/SSE、Node/Tool/Provider/MCP 契约；
- 结果：旧聊天、旧 Proposal、模型工具和 MCP 均不能直接修改事实状态。

### Iteration 3：安全、移动端和运维

- 固化对象级 ACL、信封加密、公开副本白名单、文件/SSRF/Prompt 注入防护；
- 固化行中首页、地图/卡片联动、离线包和冲突交互；
- 固化 NAS 资源预算、重任务全局串行、备份恢复和升级回退；
- 结果：覆盖主要非功能要求，性能/OCR/PDF 保留实机门。

### Iteration 4：需求追踪初检

- 发现 DD-04 文件上限初稿与 SRS 不一致；已统一为单图 20 MB、单 PDF 50 MB、单次 20 文件、家庭 20 GB；
- 发现 DD-10 人工合计误写；机器提取确认 220 个 FR + 47 个 NFR = 267，唯一 ID 无重复；
- 两项均未改变需求正文，已关闭。

### Iteration 5：范围端点校验加严

- 将检查从“需求前缀出现”加严为“每个需求域的首尾编号均匹配”；
- 首次运行因脚本未识别追踪表的缩写范围记法（如 `FR-AUTH-001～008`）产生 36 个格式误报；
- 修正解析规则后重新全量执行，所有 36 个需求域端点通过，零失败。

### Iteration 6：攻略知识库专项补充

- 新增 DD-12，补齐 GuideSource/Revision/Chunk/Claim、导入状态机、中文分块、去重、共识与冲突；
- 为避免破坏应用层加密，默认采用作用域 HMAC 盲索引，不把私有攻略写入明文 FTS；
- 可选 Embedding 仅用于最多 200 个候选的内存重排，向量加密保存且不依赖常驻向量数据库；
- 固化 EvidenceBundle，使规划模型只读取有界 Claim 和引用，不读取完整攻略正文；
- 纳入原有文档、需求范围、链接和围栏自动校验。

### Iteration 7：实现架构与设计模式审查

- 新增 DD-13，明确 16 个模块的数据所有权、公开 Facade 和禁止依赖；
- 固化六边形架构、轻量 CQRS、专用 Repository、Unit of Work、Domain Event/Outbox 和显式构造器注入；
- 为模型、地图、天气、OCR、Parser、Exporter、通知、数据库和 Agent 节点定义扩展路径；
- 增加 Python/TypeScript 导入边界和结构测试，防止实现退化为 GodService、通用 CRUD 或 SDK 泄漏；
- 采用 Slice 0～8 的纵向实现顺序，避免先搭建无法运行的大型空骨架。

## 7. 遗留决策

- Apache-2.0 是当前设计基线，正式发布前仍需完成第三方许可证复核并最终批准；
- PostgreSQL、ICS、公共旅行库、TOTP、海外服务和小红书 Worker 属于预留/后续范围；
- 不在详细设计阶段承诺第三方票价、库存或平台未公开 API 的实时性；
- 实现中若更改用户行为、权限或验收标准，必须回到 SRS 变更，不得只修改代码。
